## PLAN10 초안 작성 (draft, 미승인·미구현)

라이브 테스트 절차를 정리하다가 사용자가 "extrinsic 도 하드코딩하는 게 편하지 않나"라고 제안했고,
논의 결과 **편의 문제가 아니라 안전 문제**로 정리해 plan 을 끊었다.
경로: `docs/plans/2026_08/03_PLAN10_extrinsics_default_and_guard.md`.

### 문제

`ros2 launch cbf_base_tf base_tf.launch.py` 를 **인자 없이** 실행하면 패키지 share 의
placeholder(전부 항등)가 `/tf_static` 에 발행된다. `base` 와 `fusion_world` 가 정확히 겹쳐
**좌표 변환이 아예 안 일어나는데 RViz2 에는 정상처럼 보인다.** 오늘 검증에서 실제로 재현됐다
(placeholder 발행 + 실측 YAML 대조 → `max_error=3.0155 m`).

지금 방어는 "사용자가 매번 `extrinsics:=` 절대경로를 손으로 붙인다" 뿐 — **사람 기억력에
안전을 맡긴 상태**다.

### 이번 판단

| 변경 | 내용 |
|---|---|
| ① 기본값 하드코딩 | `launch` / `static_tf_node` 기본값을 `/home/pc/cbf_ws/logs/base_cam_extrinsics.yaml` 절대경로로 |
| ② **항등변환 거부 가드** | 세 transform 이 **전부** 항등이면 발행 거부 + exit 2. `allow_placeholder:=true` 만 탈출구 |
| ③ placeholder rename | `config/base_cam_extrinsics.yaml` → `base_cam_extrinsics.example.yaml` |

- ②가 실질적 해결책이다. ①만으로는 다른 경로를 넘겼을 때 함정이 남는다.
  **경로와 무관하게 항등변환 자체를 못 나가게** 해야 끝난다.
- 하드코딩이 재측정을 방해하지 않는다: `measure_base_cam.py --out` 기본값이 같은 경로라
  **다시 재면 자동 반영**된다. 편의와 안전이 같은 방향.
- 항등 판정 임계값은 `check_tf_to_base.py:is_placeholder()` 와 **동일하게** 쓰기로 했다.
  두 곳 기준이 다르면 한쪽만 잡는 상황이 생긴다.
- **`all()` 이지 `any()` 가 아니다** — transform 하나가 항등인 건 정상일 수 있다.
  잘못 짜면 멀쩡한 설정에서 노드가 안 뜬다. 가드레일·검증(7번)에 명시했다.

## base↔camera 체인 코드 감사 (orientation 보존 여부) + ★ 게이트 역효과 가설

사용자 질문: "camera to base tf 코드가 제대로 되어 있나, **오리엔테이션까지 반영돼 있나**".

### 결론 1 — 코드는 정확하다. orientation 은 어디서도 안 떨어진다

검증 경로:

```

  → [Markley 쿼터니언 평균] → YAML(quat xyzw) → static_tf_node → /tf_static → tf2
```

| 구간 | 회전 오차 |
|---|---|
| 회전행렬 ↔ 쿼터니언 왕복 (랜덤 2000개, 180° 근처 포함) | `2.4e-06 deg` |

- 복원된 quat 이 입력과 소수점 6자리까지 동일. RPY 로 풀면 `yaw 138.07 deg` 로 실측 YAML 과 일치.

  전 구간 일관됨을 코드로 대조.
- 합성 카메라가 본 마커가 **ID 0, 1** — 7/24 실측에서 zed1 이 본 것과 동일. 기하 모델이 현실과 맞다.

**즉 데시미터 오차는 코드 결함이 아니다.** (이건 기존 결론과 같으나, 이번엔 orientation 경로까지
포함해 확인했다.)

### 결론 2 — ★ `--ambiguity-ratio 0.3` 게이트가 이 리그에서 **역효과**일 가능성 (새 발견, 가설)

태그 화면크기 **34 px**(10cm @ 1.93m) 조건에서 코너 노이즈를 넣고 40회씩 반복:

| 코너 노이즈 | 게이트 | 채택률 | 위치오차 중앙/최악 | 회전오차 중앙/최악 |
|---|---|---|---|---|
| 0.1px | ON | 99.5% | 1.6 / 3.6 mm | 0.03 / 0.08° |
| 0.3px | **ON** | 58% | 5.4 / 15.0 mm | **0.13** / 1.09° |
| 0.3px | OFF | 100% | 5.0 / 12.5 mm | 0.52 / 3.00° |
| 0.5px | ON | 30% | 14.6 / 52.3 mm | 1.58 / 6.72° |
| 0.5px | OFF | 100% | 13.1 / 25.9 mm | 1.55 / 4.56° |
| **1.0px** | **ON** | **12%** | 81 / **1515** mm | 7.64 / **51.1°** |
| **1.0px** | OFF | 100% | **58 / 93** mm | **2.76 / 6.42°** |

- **게이트는 0.3px 이하에서만 이득**이다. 0.5px 부터 무의미해지고 **1.0px 에서는 크게 해롭다**
  (최악 1515mm/51° → 93mm/6.4°).
- 원인: 게이트가 88% 를 버려 표본이 12% 만 남는다. **평균의 효과가 사라지고** 남은 것도 편향된
  부분집합이다.
- **현장 관측과 일치한다.** 7/24 worklog: "채택 프레임이 60→9로 널뛰고 교차검증이 552~1022mm로
  요동" → 채택 9/60 = **15%** 로 위 표의 1.0px/ON 구간(12%)이고, 오차 크기도 같은 자릿수다.
- **따라서 데시미터 오차의 상당 부분이 물리 한계가 아니라 게이트 설정 탓일 수 있다.**

**한계(정직하게)**: 시뮬레이션은 코너 노이즈를 i.i.d. 가우시안으로 뒀다. 실제 검출 노이즈는
조명·모션블러·서브픽셀 보정 편향이 섞여 상관을 가질 수 있어 게이트 거동이 다를 수 있다.
**현장 재확인이 필요한 가설**이다.

### 확인 절차 (코드 수정 불필요 — 이미 CLI 옵션)

```bash
conda activate zed && cd ~/cbf_ws
# (A) 현재 설정으로 3회
python3 scripts/measure_base_cam.py --save-debug /tmp/gate_on.png
# (B) 게이트 사실상 해제로 3회
python3 scripts/measure_base_cam.py --ambiguity-ratio 0.99 --save-debug /tmp/gate_off.png
```

### git 스냅샷 관련 정정 (memory.md 반영)

기존 memory 에는 "git 미설치" 로 적혀 있었으나 **git 2.34.1 은 설치돼 있다.** 실제 원인은
`/home/pc/cbf_ws/.git` 이 **빈 디렉터리로 존재**한다는 것 — `codex_exec_plan.sh` 는
`[ ! -d .git ]` 일 때만 `git init` 을 하므로 이 분기를 비껴가고, 이어지는 `git status` 도
실패해 `SNAP=unknown` 이 된다. 이번 실행도 **롤백 지점 없이** 진행됐다.

고치려면 빈 `.git` 을 지우거나 직접 `git init` 하면 되지만, **지금 상태로 커밋하면
`.mcp.json.example` 의 실제 API 키가 히스토리에 박힌다.** 키 정리가 선행돼야 한다.
