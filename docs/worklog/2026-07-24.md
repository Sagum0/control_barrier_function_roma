## ArUco base TF 정밀도 진단 (교차검증이 왜 크게 나오나)

교차검증(704mm/16°)의 원인을 파고든 결과, **datum 문제가 아니라 측정 기하의 한계**로 결론.

### datum 방향/매핑은 정확 (검출로 확인)

`measure_base_cam.py --save-debug`의 주석 이미지를 확대해 ID↔면을 대조:

- zed1(앞-우측)이 본 마커 = **ID 0(오른쪽 -Y면), ID 1(정면 +X면)**.
- zed2(앞-좌측)이 본 마커 = **ID 2(왼쪽 +Y면)** (+정면). zed2는 정면 마커가 IPPE 모호성으로
  폐기돼 **프레임당 ID 2 하나만** 채택.
- datum의 `id1=정면(+X)`, `id0=오른쪽(-Y)`, `id2=왼쪽(+Y)`, `up=+Z`와 **전부 일치**. 태그는 정사각
  (마름모 아님)으로 똑바로 서 있어 up=+Z 확인.
- 결론: 방향/ID/up 파라미터는 오류 없음.

### 큐브 치수: 101→99mm로 정정(사용자 대략 실측)

`logs/base_cube_datum.json`: `tag_size_m` 0.10 유지, 반변 `0.0505→0.0495`(겉면 99mm). 1mm 변화라
교차검증엔 영향 미미.

### 교차검증이 노이즈 지배임을 확인 (실행마다 요동)

같은 배치로 3회 실행:

|------|-----------|-----------|----------|
| 1 | 31/60 | 38/60 | 704mm / 16° |

채택 프레임이 60→9로 널뛰고 교차검증이 552~1022mm로 요동 → **노이즈 지배 확정.** datum·치수
문제가 아님.

### 노이즈 원인 (물리)

화면상 태그가 작아서(100mm @ 1.9m ≈ 34px, ZED-M HD720 광각 fx≈650). 두 축으로 증폭:

1. **거리(depth) 오차** ∝ 거리² / (fx·태그크기) → 작은 태그·먼 거리에서 코너 ±0.5px가 수 cm로.
2. **정사각 마커 IPPE flip 모호성** → 정면에 가까운 마커는 두 pose 해가 비슷해 프레임마다 뒤집힘
   (회전 노이즈 주범). `--ambiguity-ratio 0.3` 게이트가 대량 폐기(그래서 채택률↓), 잔여도 흔들림.

평균(median translation + Markley quat)은 **zero-mean 랜덤 노이즈만** 줄이고(≈1/√N), 계통 오차나
flip(양봉)은 못 지움 + 표본이 적어(9~60) 효과 제한.

### 결론 / 방침

- **ArUco base TF는 이 리그(10cm 태그·1.9m)에서 데시미터급이 한계.** 이건 id0/id1 융합과 무관하고
  (융합은 ZED360 extrinsic 사용), base를 cm급으로 올려야 할 때만 문제.
- 정밀화가 필요해지면: **ChArUco 보드(A3~A2, ~30cm+)를 base 위치에 세우기**가 최선(코너 다수 →
  평균↑, flip 없음). 또는 측정 시 큐브를 더 가까이(단 base 위치 이동). 그때 정확한 스펙 조사.
- base 정밀화는 CBF/로봇좌표 연동 시점(현재 스코프 밖)의 과제 → **지금은 기록만 하고 보류.**
