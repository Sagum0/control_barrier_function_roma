### 추가 (같은 날, SDK 필드 조사)
- pyzed 5.4.0 introspection 실측: `sl.BodyData` 22개 속성. 현재 JSONL 8개·ROS2 브리지 2개만 기록.
- 미기록 핵심: `velocity`(칼만 기반·지연 보고됨), `position_covariance`, `keypoints_covariance`(N,6),
  `global_root_orientation`, 3D bbox류, `Bodies.timestamp`(현재 `time.time()` 사용 중), `FusionMetrics`
  (켜 놓고 호출 안 함). fused 출력에서 `keypoint_2d`/`bounding_box_2d`/`mask` 는 빈 값(이미지 공간 필드).
- Python `keypoints_covariance` vs C++ `keypoint_covariances` 이름 불일치 → getattr 방어 필요.
- 저장 포맷 판단: **탐색 단계는 JSONL(py), bag 은 커스텀 msg 확정 후 별도 plan**. 진짜 raw 는 SVO2 녹화.
- 사용자 결정: **이미지 무조건 저장** → PLAN11 에 카메라별 LEFT MP4 기본 저장 + 전 레코드
  `frame_idx`(JSONL↔MP4 join 키) 반영. `--no-video` 는 탈출구. 인코딩의 30fps 영향은
  metrics `received_fps` 로 라이브 판정.

참조 plan: 없음 — 코드 변경이 없어 plan 불요. 게이트 기본값 뒤집기 등은 보류(아래 참조).

## PLAN11 실행 결과

- 신규 `zed_fusion_fulllog.py`는 기존 bodytrack 헬퍼 8개를 import해 sender/Fusion 구성을
  재사용한다. fused(BODY_34)와 raw(BODY_18)의 지정된 전 필드, `Bodies.timestamp`, wall
  timestamp, 컨테이너 상태를 JSONL로 기록한다.
- 기본으로 카메라별 LEFT BGRA 영상을 BGR MP4(`mp4v`)로 저장하고, fused에는 serial별 dict,
  raw에는 카메라별 int `frame_idx`를 기록한다. `--no-video`와 `--no-raw` 탈출구를 제공한다.
- `--metrics-every` 주기로 FusionMetrics를 기록하며 모든 레코드는 `NaN`/`inf`를 `null`로
  정규화해 `allow_nan=False` JSON 직렬화를 통과한다.
- `--record-svo DIR`은 sender open 직후 카메라별 H264 SVO2 녹화를 시도하고, 실패해도 경고 후
  주 로깅을 계속한다. meta에는 전체 CLI 인자, config/SDK/serial/body format/좌표계와 영상·SVO
  경로를 남긴다.
